# dsh-agent-builder

**像 agent 产品经理面试官一样，把一句业务需求问成一份可执行的 agent 产品定义，再据此构建并安装 DeepSeek Harness 的 preset。**

产品定义先于配置：没有 `SPEC.md` 不写 YAML。

## 它解决什么问题

在 DSH 里「做一个 agent」不是改一个配置文件，而是组合若干插件行。但真正的难点不在配置，而在**把业务说清楚**：

- 这个 agent 替谁办事、解决哪一类问题、明确不做什么？
- 一次完整对话怎么走、在哪结束、卡住怎么办？
- 它能自己执行什么、什么必须人工点头、什么话绝对不能说？
- 每个工具叫什么、何时调用、入参返回是什么、失败怎么说、有没有副作用？
- 记住谁、记什么、绝不记什么、留多久、什么时候召回？
- 依据哪份文档回答、文档冲突谁优先、没有答案时怎么办？
- 什么情况转人工、交接什么、没有人工在线怎么办？
- 验收用例是什么、什么算不通过？

这个 skill 把这些问清楚，写成 SPEC，再翻译成 DSH 的 persona / 工具 / 记忆 / 知识配置。

## 十一个模块

| # | 模块 | 产出 |
|---|---|---|
| 1 | 业务与角色 | 服务对象、问题、不做的事、成功标准 |
| 2 | 任务与对话流程 | 主流程、卡点处理、结束条件 |
| 3 | 能力边界 | 可自主 / 需人工 / 禁答 / 拿不准 |
| 4 | 工具定义 | 每个工具的名称、触发、入参、返回、失败、副作用 |
| 5 | 记忆 | 记谁、记什么、不记什么、留多久、何时召回 |
| 6 | 知识 | 知识源、更新频率、冲突优先级、无答案处理 |
| 7 | 交互规则 | 语气、澄清策略、确认策略、附件、语言 |
| 8 | 异常与升级 | 转人工触发、交接模板、兜底、超时 |
| 9 | 安全与合规 | 个人信息、留痕、越权防护、合规话术 |
| 10 | 运行与渠道 | 渠道、模型、并发、上下文预算 |
| 11 | 验收标准 | 必须答对 / 必须拒答的用例 |

每个模块的**问题、为什么问、典型答案、怎么落配置**都在 `references/interview-playbook.md`。

## 面试怎么进行

- **一次只谈一个模块**，3–6 个问题，每题带推荐默认值和典型答案
- **每模块结束必须复述定稿**，PM 确认后才进下一个
- **答案即时写入 `SPEC.md`**，不攒到最后
- PM 说不清的，给方案让他选，不问实现细节
- 简单 agent 可能 3 个模块就问完；带交易动作的可能 11 个全要问

## 面试后

1. **适配性评审**——强一致实时数据 / 不可撤回承诺 / 其实只要知识问答，这三种情况当面说清
2. **生成组合包**——`SPEC.md` + `package.json` + `cordis.patch.yml`（+ `index.js`）
3. **安装**——`install_bundle`，只有 `applied` 算装好
4. **验收**——按模块 11 逐条跑，记进 SPEC

## 三条来自实测的硬约束

1. **profile 插件不能 `import '@deepseek-ai/dsh-tools'`** —— 该包只在 DSH 安装目录，profile 的 `node_modules` 解析不到。必须直接传普通对象给 `ctx.tools.register()`。
2. **`parameters` 是标准 JSON Schema** —— `type: 'object'` + `properties` + `required` 数组。
3. **`output.schema` 与 `output.render` 都是必填**。

## 已知边界

- **preset 只有 Web/Desktop 会组合**：`dsh headless` 与 `dsh acp` 明确不挂 preset 名册（源码注释 "This bundle composes no preset roster"），所以 CLI 无法端到端验证 preset 会话，最终 UAT 必须在新 Web 会话里做。
- 工具、记忆可以单独用临时全局挂载在 headless 里验证。
- 默认拒绝给外部用户挂 `bash` / 文件写入 / 联网工具。
